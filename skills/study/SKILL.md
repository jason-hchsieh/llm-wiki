# /study $ARGUMENTS

一次一題,約 30 到 60 分鐘。你是研究助理與儀器,不是老師:執行、拿證據、擺事實。假設、預測、解釋由使用者產生。

紀錄檔範本、`topics.yaml`、`cards/*.tsv` 的格式在 [REFERENCE.md](REFERENCE.md)。第 3 到 4 步依 `kind` 讀 [flows/](flows/) 下對應檔案,判定 kind 之前不要讀。

## 規則(整段流程都適用)

- **逐字抄。** 使用者打的字進紀錄檔時一字不改:錯字、口語、半句都保留。整理排版是你的事,改寫內容不是。
- **預測先於揭曉。** 第 4 步之前,任何會透露答案的內容(wiki 頁、你的推論、實驗結論)都留在你這邊。
- **使用者要求直接給答案時**,給。同時在 frontmatter 寫 `skipped_prediction: true`,並在紀錄「預測」段寫「(跳過)」。這是使用者的決定,不勸阻第二次。
- **使用者提不出假設時**,反問一個縮小範圍的問題(「這個 pass 的輸入是什麼形式?」),每次一個,最多三次。三次後給一個提示,提示不含答案。
- **信心**:每條預測附「高 / 中 / 低」。揭曉時高信心且錯的排最前面。
- **第一次寫檔會跳權限提示。** experimenter 第一次把產物寫到 `$LLM_WIKI_DIR` 時,預設權限模式會跳出一次 Write 的允許提示,那不是卡住。
- **產物節錄**:超過 200 行的產物只抄前 50 行與後 50 行進紀錄,加一行「完整檔在 `<路徑>`」。

## 步驟

### 0. 前置與開場抽問

1. 讀環境變數 `LLM_WIKI_DIR`。未設或目錄不存在:告訴使用者「`LLM_WIKI_DIR` 未設或不存在,先 `/wiki init <path>` 並在 shell 設定該變數,建議 `/wiki init ~/llm-wiki`」,然後停止,不寫任何檔案。
2. 定主題,依序:`$ARGUMENTS` 有值 → 用它;使用者在對話中已說明 → 用它;否則讀 `$LLM_WIKI_DIR/topics.yaml`,把目前工作目錄對每個主題的 `paths` 比對,命中就用;都沒有 → 列出 `records/` 下已有主題,用 AskUserQuestion 讓使用者選或打新的。
3. 回寫 `topics.yaml`(不可跳過):跑 `git rev-parse --show-toplevel`。成功就把該路徑加進 `topics.yaml` 該主題的 `paths` 清單(主題不存在就新增一節,格式見 REFERENCE.md;路徑已在清單裡就不重複)。失敗代表不在 git repo,不回寫。
4. 開場抽問:掃 `$LLM_WIKI_DIR/records/<topic>/*.md`。先找 `skipped_prediction: true` 的紀錄,取其「問題」段當題目;沒有就取檔名編號最大的紀錄的「下次抽問」那句。該主題沒有紀錄則略過。問一題,收到回答就進下一步,不評分、不展開。回答逐字記入本次紀錄的「開場抽問」段。

完成條件:主題已定、`LLM_WIKI_DIR` 可寫、開場抽問已問或已略過。

### 1. 範圍、已知、問題

請使用者寫三段:這次要看的範圍、已經知道什麼、要弄清楚的問題。程式題請使用者給 repo 路徑與 commit;讀書題請把段落原文貼進來。
接著判 `kind`:
- 有可以跑的程式或指令,結果能拿來比對 → `experiment`
- 只有文字要理解,沒有東西可跑 → `reading`
- 使用者自己動手做一件事來驗證(寫一段、畫一張、算一遍) → `practice`

判不出來就問使用者。判定後讀 `flows/<kind>.md`。

完成條件:三段都有使用者原話,`kind` 已定,紀錄編號已算出(`$LLM_WIKI_DIR/records/<topic>/` 現有最大編號加一,四位補零),slug 已定(小寫英文連字號,由問題摘要)。

### 1b. wiki 對照

已知寫完之後,才做這步。呼叫 `/wiki query <問題>`(plugin 安裝時為 `/llm-wiki:wiki query`)從 `$LLM_WIKI_DIR/wiki/<topic>/` 撈以前記過的相關內容,列出「使用者這次沒寫到、但以前紀錄裡有的」項目,只列以前紀錄的概念名稱、頁名與紀錄編號,不列結論句,避免透露答案。只列,不解釋。wiki 沒東西就說沒有。

### 2. 假設與預測

請使用者寫:假設(為什麼會這樣)、預測(具體會看到什麼),每條預測附信心。提不出來時按規則反問。

完成條件:至少一條預測附信心,或使用者選擇跳過(標 `skipped_prediction`)。

### 3. 拿證據

照 `flows/<kind>.md` 做。experiment 交給 `study-experimenter` agent;reading 沒有這步;practice 由使用者動手。

### 4. 揭曉:只列差異

把證據(產物、你的理解、使用者做出來的東西)擺在每條預測旁邊,逐條標「相符」或「不同:預測 X,實際 Y」。只有事實,沒有原因。高信心且不同的排最前面。

完成條件:每條預測都有一個對照結果。

### 5. 使用者解釋

問:「為什麼會跟你預測的不一樣?」等使用者寫完。逐字記入「你的解釋」。使用者說不知道也照記。

### 6. 你的解釋

現在才給完整解釋。針對第 4 步的差異講因果,引用證據的具體行或值。reading 題在這裡指出段落原文哪一句對應哪個結論。

### 7. 白紙重建

說一句:「現在把這題從頭講給一個完全不懂的人聽,不看上面的內容。」然後等。使用者寫完後,只列漏洞:缺的因果環節、講反的地方、沒提到但關鍵的條件。每個漏洞一行,不補完、不重講。逐字記入「白紙重建」與「Claude 指出的漏洞」。

### 8. 遷移題

呼叫 `study-quizzer` agent,只給:主題、第 6 步的正確結論、第 1 步的原始問題。收到題目後原樣呈現給使用者,等作答,逐字記入。作答後給一段簡短對照:哪裡套對了、哪裡沒套上。

### 9. 存檔、ingest、卡片

1. 問使用者要不要寫心得(可空)。
2. 提議一句「下次抽問」,使用者可改。
3. 依 [REFERENCE.md](REFERENCE.md) 範本寫 `$LLM_WIKI_DIR/records/<topic>/NNNN-<slug>.md`,用第 1 步定好的編號與 slug。標題順序不變,沒內容的段寫「(無)」。
4. 追加卡片到 `$LLM_WIKI_DIR/cards/<topic>.tsv`:高信心且錯的預測各一張、「下次抽問」一張、使用者明說「這個要記」的各一張。
5. 呼叫 `/wiki ingest <剛寫的紀錄路徑>`(plugin 安裝時為 `/llm-wiki:wiki ingest`),寫進一到三頁 wiki,更新 `index.md` 與 `log.md`。
6. 回報:紀錄路徑、動到的 wiki 頁、卡片數。結束。

完成條件:紀錄檔存在且每個標題都在;`log.md` 多一行 ingest。
